# Technical specification

**AR-1** — The launcher shall load the platform configured by its own checkout,
independently of the caller's directory, and shall refuse Python below 3.11.

**AR-2** — The runner shall retain each gate verdict. A gate crash shall report
unavailable evidence, its exception and traceback, while later gates still run.
Faults shall take precedence over unavailable results. A declared gate whose
module is absent and whose declaration names a repair command shall fail with
the module path and that command while later gates still run; any other
import failure is unavailable evidence. Process control shall propagate to the
caller.

**AR-3** — Shared gates shall inspect owned indexed inputs. Families shall import
only the public API, and synced configuration shall match deterministic output.

**AR-4** — Each standards gate shall reject a fault, accept its repair and report
unreadable inputs as unavailable. Refusal tests shall check the finding text.

**AR-5** — Commit checks shall inspect every commit selected by the configured
range, including branch commits and merge parents. Resolved empty ranges shall
pass; unresolved endpoints and incomplete shallow history shall be unavailable.
Installed hooks shall run the checkout's pinned launcher. The message hook shall
check the pending message; pre-commit shall run standards excluding old commits.

Without an explicit selection, schedule, workflow_dispatch and
repository_dispatch events introduce no commits and shall report that push and
pull_request check ranges. Other unrecognised events shall be unavailable.

**AR-6** — Providers shall format and lint only owned indexed source files,
excluding every submodule. Formatter/analyser versions and shared configuration
shall come from the pinned platform. C++ lint shall preserve directory config
inheritance, check every translation unit's compile command and reach owned
headers. Build evidence shall cover a complete compilation, and warnings shall
fail. Language-selected sync output shall not introduce C++ tools into a
Python-only repository; overlays shall retain base lists and be deterministic.

**AR-7** — A gate whose owning provider is absent from the declared languages
is not applicable, contributes no CI obligation, and is listed with its reason.
Unavailable gates of declared providers retain strict CI skip/failure behavior.

**AR-8** — The C++ CMake API shall retain strict diagnostics, hardening,
source-scoped vendor diagnostics, sanitizer ordering, module tests, documentation
examples and fuzz instrumentation. Install/export identity and compatibility
shall derive from explicit package/version arguments. The consumer gate shall
install to an isolated prefix and build indexed consumers after relocating it.
No embedded or SDK setup belongs in this language API.

**AR-9** — Context shall identify pinned guides/rules and local instructions for
the selected path. Withdrawn: agent installation and optional session hooks.

**AR-10** — CI rendering shall derive jobs from applicable obligations and
explicit matrices/schedules, omit undeclared providers, and retain unavailable
declared gates. Synced files shall compare exact generated bytes without parsing
YAML. The renderer shall use checkout credential refusal, non-advisory jobs and
steps, separate scheduled concurrency and immutable action references. Main runs
shall not cancel each other, and matrix legs shall have distinct groups.
Recursive pins and full history shall be checked out. Scheduled
online work shall have its own concurrency group; matrix values reach profiles
through HOUSE_MATRIX variables, with build type and C++ compiler mapping; a
matrix axis may name a CMake cache variable that every tree's configure sets from
its HOUSE_MATRIX variable.

**AR-11** — Tool preparation uses the pinned manifest, reuses compatible tools,
keeps Python packages in an ignored private environment without pip's user cache,
and requires an explicit request for native system installation. Missing prerequisites remain unavailable.
A tool run places the private environment first on its search path.

**AR-12** — Withdrawn. Agent instruction-discovery preflight is outside House.

**AR-13** — Init preserves nonempty destinations, uses a clean local platform
commit and one submodule pin per level, and emits owned community policy,
LF attributes, indexed sources and deterministic provider-selected configuration.
A Python-only family needs no C++ copies or CI allowances. A family may pin an
infrastructure checkout at a chosen path with the platform nested inside it;
templates then render that platform path, and a template that hardcodes the
default path is refused. A pin path that is empty, or that equals or lies
under a top-level path the scaffold writes, is refused before anything is
created. Family references replace the AGENTS.md route table with a reference to
the pinned family routes file; standalone repositories retain the table.

**AR-14** — Withdrawn. Requirement citations are checked by review.

**AR-15** — A CI requirement may select a nonempty single-line container_options
string for its group. It requires a resolved container image, preserves valid
text in that job only, refuses malformed quoting and unsupported --network and
--entrypoint flags, and preserves current output when absent. A declared ci.container_user shall
append --user VALUE to every job container, independently of per-group rows.
It accepts a user or user:group, may be set before an image is selected, and
has no effect on jobs without a container.

**AR-16** — A CI requirement may list nonempty single-line preparation commands.
They render, in order, as named steps after tool preparation in that group's job
only; House never runs them locally. Absent preparation preserves current output,
and synced-files refuses a removed or edited step.

**AR-17** — A public resolver, house.api.user_config_dir, shall return the
per-user configuration directory for one lowercase name. The base is the
absolute value of HOUSE_CONFIG_HOME when set, refusing a relative value; else on
Windows the roaming application-data directory, refusing when it is unset; else
on macOS the native per-user application configuration base; else the XDG base
directory when set and absolute, otherwise the native default. Context shall
report the House directory, whether local.md exists there and every directory
the repository registers under context in house.toml, in text and JSON. Review
shall keep per-user paths platform-neutral in shared text.

**AR-18** — Optional family configuration shall merge beneath repository choices,
with modules imported directly from the pinned family. Missing files, escaping
paths, forbidden keys and failed imports shall name the unavailable input.

**AR-19** — Suppression checks shall count each language against one ceiling,
report lower ceilings to commit and refuse increases. Register contents and
suppression approval shall be checked by review. Commit checks shall enforce
message format only; area choice, branch policy and merge policy are reviewed.

**AR-20** — C++ lint shall resolve trees once per invocation. Installed consumers
shall reuse producers with identical tree and arguments; expected producer
refusals shall execute separately with their named stage and message checked.

**AR-21** — The optional devcontainer sync file shall contain House editor
customizations and merge family/repository overlays. It requires build or image
and is absent from language defaults. No workspace editor files are emitted.

**AR-22** — The CMake sanitizer declaration shall register build:sanitize and
lint:sanitize, enabled only by HOUSE_MATRIX_SANITIZE=ON, with Debug last and
leak detection enabled. A profile with the same declared name is refused.
